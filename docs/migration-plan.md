# gravity2018.co.jp 移管計画書

作成: 2026-07-28 ／ 最終更新: 2026-07-28
方針: **Equal Core既存契約のお名前.comレンタルサーバーに gravity2018.co.jp を追加**して公開・メール運用する（2026-07-28決定）。
ドメインの移管先も**お名前.com**とし、ドメイン・サーバー・メールを一元管理する。

前提の合意事項（お客様へ伝達すること）:
- サーバーはEqual Core（御社）管理の契約に相乗りする形になる
- 御社サーバー契約の自動更新・支払い方法を確認しておくこと（失効＝お客様メール停止に直結）

## 全体の流れ

```
STEP1 現制作会社へ確認         ✅ 完了 (ドメイン移管可・AuthCode入手・メールPOP確定)
STEP2 サーバー準備             → お名前.com既存サーバーにドメイン追加 (新規契約不要)
STEP3 事前準備                 (サイト設置 / メールアカウント作成 / GASフォーム接続 / 動作確認)
STEP4 ドメイン移管 + ネームサーバー変更  ← サイトとメールが新サーバーに向く
STEP5 公開後作業               (SSL確認 / Search Console / 旧契約解約)
```

### 追加回答2（2026-07-28）: POP運用・Webメールなし

- 受信方式: **POP**（過去メールは各PCのメールソフトに保存済み → サーバー側データ移行は不要）
- Webメール: 利用なし
- 結論: **メール移行は「新サーバーに同名アカウント作成＋各端末の設定変更」のみでよい**

残る唯一の注意点 = **DNS切替の浸透中（数時間〜最大72時間）に旧サーバーへ配送されたメール**。
POPホスト名が mail.gravity2018.co.jp 等の場合、切替後は新サーバーを指すため旧サーバーに残った分を取り込めない。
対策（いずれか）:
- 制作会社に「旧サーバーへ直接アクセスできるホスト名またはIPアドレス」を確認しておき、
  切替後に旧サーバー宛の設定を一時的に残して最終受信する（推奨）
- 切替をメールの少ない時間帯（金曜夕方〜週末）に実施し、取りこぼしリスク自体を小さくする

### メール移行ワークストリーム（必須）

1. **アカウント一覧の入手**（回答待ち）
2. 制作会社へ追加確認:
   - 各アカウントの受信方式は POP か IMAP か（IMAPの場合サーバー上のメールデータ移行が必要）
   - Webメールの利用有無
   - 切替後も2週間程度は旧サーバーのメールボックスへアクセス可能か
3. 新サーバー(お名前.com)側に**同名アカウントを全て作成**（新パスワードを発行し一覧化）
4. ネームサーバー切替の**当日〜翌日**に、スタッフ各端末のメール設定を新サーバーに変更
   - 変更内容: 受信/送信サーバー名（お名前.comレンタルサーバー指定のホスト名）・パスワード
   - 設定手順書を事前に用意し、お客様に配布する
5. IMAP利用者がいる場合: 旧サーバーのメールを新サーバーへコピー（メールソフト上でフォルダをドラッグ移行 or 移行ツール）
6. **注意**: 切替の谷間でもメールは消えない（DNS浸透中は旧サーバーに配送→旧側でも受信可能なため、2週間は旧契約を維持する）

### 切替日の段取り（お客様側への案内が必要）

- 切替日はお客様と合意して決める（平日午前推奨・営業時間内にテストできる日）
- 当日: NS変更 → サイト表示確認 → メール設定変更（各端末） → 送受信テスト
- スタッフへの事前アナウンス「◯月◯日にメールの設定変更が必要です」をお客様から周知してもらう

## STEP1(旧): 現制作会社への確認事項（送付済みの質問リスト）

> 1. ドメイン「gravity2018.co.jp」はどちらの事業者（レジストラ）で管理されていますか？
>    ドメインの管理を当方（または貴社経由でお客様）へ移す場合の手続きを教えてください。
>    （ドメイン移管の場合: AuthCode（認証コード）の発行と、移管ロック解除をお願いします）
> 2. ドメインだけ継続管理いただき、ネームサーバー（DNS）の変更のみ対応いただくことは可能ですか？
> 3. 現在 @gravity2018.co.jp のメールアドレスは運用されていますか？
>    運用中の場合、メールアカウントの一覧（アドレスのみで可）を教えてください。
> 4. 現在のDNSレコード一覧（特にMX・TXT/SPF・DKIM）を共有いただけますか？
> 5. 現サーバー・CMSの契約解約はいつ付けで可能ですか？ 解約希望の連絡はいつまでに必要ですか？
> 6. 切替完了まで現サイトはそのまま公開を継続いただけますか？

**重要**: 3・4の回答が来るまでDNSは絶対に変更しない。メールが止まる事故を防ぐため。

## STEP2: サーバー準備（お名前.com既存サーバーを利用・新規契約不要）

- Equal Core既存契約の**お名前.comレンタルサーバー**（マルチドメイン無制限・無料SSL・メール対応）に相乗りする
- お名前.com Navi / サーバーコントロールパネルで「ドメイン追加」に **gravity2018.co.jp** を登録
  （この時点ではDNSは旧のままでOK。追加しても現行サイトには影響しない）
- 御社契約の自動更新・支払い方法を確認しておく（失効＝お客様メール停止に直結するため）

## STEP3: 事前準備（DNS切替の前に済ませる）

1. **メールアカウント作成**: 制作会社から届くアカウント一覧の全アドレスを、コントロールパネルの
   メール設定で同名作成（新パスワードを発行し一覧化 → お客様へ安全な方法で渡す）
2. **サイトのアップロード**: `roots-website-release.zip`（本番用パッケージ・生成済み）を
   gravity2018.co.jp の公開ディレクトリに展開（ファイルマネージャ or FTP）
   - パッケージの再生成はローカルで `node tools/build-release.js`
3. **動作確認**: DNS切替前の表示確認（コントロールパネルの動作確認URL機能、
   なければPCのhostsファイルにサーバーIPを書いて確認）
4. **フォーム接続**: docs/contact-form-setup.md の手順でGASをデプロイし、
   `js/site-config.js` の contactEndpoint を設定 → release再生成 → 再アップロード
   - 通知先はお客様のメールアドレス（切替後は @gravity2018.co.jp も使用可）
5. **プライバシーポリシー仕上げ**: 制定日を記入し、ドラフト注意書き（オレンジ枠）を削除
6. **無料SSL**: コントロールパネルで独自SSLを申請（DNS切替後に有効化される）

## STEP4: ドメイン移管 + ネームサーバー変更

1. **お名前.comへドメイン移管申請**（gravity2018.co.jp・AuthCode使用）
   - お名前.com Navi「ドメイン移管」→ 移管申請 → 名義（株式会社gravity）宛の承認メール等に対応
   - .co.jpの移管は完了まで数日〜2週間かかることがある
2. 移管完了後、お名前.com Naviで**ネームサーバーをお名前.comレンタルサーバー指定のもの**に変更
   （同一社サービスのため管理画面の案内に従えば自動連携される）
3. 浸透まで数時間〜最大72時間。旧サイトは浸透中も表示されるため実質ダウンタイムなし
   ※公開を急ぐ場合は、移管完了を待たずにRIDE側管理画面でネームサーバーのみ先に変更する順序も可
   （その場合は変更先のネームサーバー名をコントロールパネルで確認してから実施）

**切替直前チェックリスト**
- [ ] 新サーバーにメールアカウント作成済み（一覧の全アドレス）
- [ ] SPF等のTXTレコードを新DNS側にも設定（旧DNSに独自のSPF/DKIMがあった場合のみ手動移設）
- [ ] 動作確認でサイト全ページ表示OK
- [ ] フォームのテスト送信OK（GAS接続済み）
- [ ] お客様へ切替日を連絡済み（当日メール設定変更が必要な旨・平日午前 or 金曜夕方）

## STEP5: 切替後の作業

- [ ] https://www.gravity2018.co.jp/ が新サイトで表示されることを確認（スマホ回線でも確認）
- [ ] SSL（https）有効・鍵マーク表示を確認。http→https/wwwなし→www有りのリダイレクトを.htaccessで設定
- [ ] メールの送受信テスト（全アカウント）＋各端末の設定変更（手順書を配布）
- [ ] 旧サーバーに残った浸透中受信分の最終取込（旧サーバー直アクセス情報が入手できた場合）
- [ ] Google Search Console にサイト登録 → sitemap.xml を送信
- [ ] GA4を発行して site-config.js に設定（任意）
- [ ] Googleビジネスプロフィール等の住所も新住所（玉川町2-9-7）に更新されているか確認
- [ ] 1〜2週間問題がないことを確認してから、現制作会社の契約を解約
  （解約前に旧CMS内に未取得のデータがないか最終確認）
